# TASE-001 — 项目主计划 v1.0

**日期：2026-10-21｜时区：Asia/Singapore｜截止：2026-11-06 23:59。**

状态：范围与有界启动计划已确定；模型部署、Gate 实现与治理效果尚未验证。所有数值预算和实验阈值是本项目设计，不是课程规定。依据见 [SOURCES](SOURCES.md)。

## 1. 一句话项目

在官方 LIBERO-adapted GR00T N1.7 的原生动作执行路径中，设计执行前的任务授权 Safety Gate，减少指定非目标物体的错误抓持／抬升，并实测其误拦截、任务损失和运行成本。

**GR00T 在这里直接产生 LIBERO action，不经过 WBC 或我们其他研究的 EEF 适配。** “直接”指经匹配的官方 processor、wrapper 和 LIBERO/Panda 控制器进入仿真，不表示模型直接输出电机力矩，也不表示模型绕过低层控制。

## 2. 课程问题与研究问题

### 2.1 治理风险

授权任务是操作 A，但 VLA 可能产生对 B 的抓持动作。动作格式合法、可被控制器执行，不等于符合任务授权。本项目聚焦 Guardrails / risk-based autonomy，不泛化为所有人身或设备安全。

### 2.2 治理要求 GR-01

每次自动执行候选动作前缀前，应使用可信任务规范和当前执行状态检查是否存在超出任务授权的物体操作风险。超过已冻结干预规则的候选不得进入主环境执行；决定、依据、版本和实际结果应可追溯。检查失败不得默认为允许执行。

### 2.3 研究问题

固定模型与原生执行链后，Gate 能否减少错误物体事件？它保留多少正常任务能力，需要多少干预和计算成本？错误属于漏检、几何过保守、信息不足、预测不准还是集成问题？

### 2.4 贡献边界

贡献是可运行的任务授权门控、可验证的执行边界、独立事件评价和风险—任务权衡。不贡献新的基础模型、机器人控制器、视觉检测器或物理安全认证。

## 3. 范围决定

| 维度 | 必做范围 | 不做范围 |
|---|---|---|
| Policy | 官方 `nvidia/GR00T-N1.7-LIBERO` 的 Object 适配权重 | 从 base 重训、定制轨迹头、新模型挑选竞赛 |
| 环境 | LIBERO Object / Panda / 原生仿真接口 | WBC、实机、Go2、ARX5、换仿真器 |
| 治理问题 | 指定非目标物体错误抓持／抬升 | 通用任务规划、所有碰撞、所有释放错误 |
| 动作干预 | 放行原前缀，或阻止并结束自主 episode | 自动修轨迹、平滑、重定时、无限重试 |
| 信息 | Gate 允许可信 TaskSpec 和仿真状态 | 不将对象真值额外输入 VLA |
| 评价 | 固定候选集＋B0/G 闭环对照 | 只看成功视频、只看拒绝率 |

初选三个任务：alphabet soup、cream cheese、ketchup 分别放入 basket。每个任务的真实对象名单、语言、BDDL、assets 和初始化必须独立核验；不得复制一个通用 distractor 列表。

## 4. 核心方法

`policy action → 已解析执行前缀 → shadow prediction → 任务授权风险 → ACCEPT / REJECT → native execution / abort → record`。

第一版采用透明的几何检查：预测前缀执行期间，夹爪闭合或保持抓持时的抓取区域是否接近/重叠指定非目标物体。距离余量在校准集选择；不把短暂缺乏目标距离进展当作违规。

拒绝意味着不执行候选动作并结束仿真中的本次自主运行。它不是实机安全制动，也不是成功恢复。下一阶段若研究恢复，必须单独修改协议。

详细接口和验收见 [ARCHITECTURE](ARCHITECTURE.md)；事件、对照和统计见 [EXPERIMENT_PROTOCOL](EXPERIMENT_PROTOCOL.md)。

## 5. 主要可行性风险

| 风险 | 为什么可能阻塞 | 先取得的证据 | 失败时的动作 |
|---|---|---|---|
| 原生 baseline 未跑通 | 可能是依赖、观测、权重或控制错配 | 真实模型＋完整 episode＋正常条件重复完成 | 先修接口，不开发更复杂 guard |
| 正常任务可做但违规极少 | 视觉退化可能仅造成抓空/停顿 | 预定义开发条件的事件频数及人工核查 | 单列受控意图错配测试；不伪造自然违规 |
| shadow 不一致 | 控制器/随机状态/缓存遗漏 | 同快照同动作、接触与状态比较 | 提交缩减到即时监测的 change request |
| 短前缀不含实际违规 | 靠近不等于抓持/抬升 | 前缀标签与完整 episode 事件时间 | 保留双层评价，不能夸大预测窗 |
| Gate 全拒绝 | 低违规可能仅来自不执行 | 正常干预率、任务成功、覆盖率 | 报告没有可接受工作点，不改测试答案 |
| 重型资源或时间不足 | 渲染、推理、shadow 都有成本 | 真实 wall time、峰值显存、磁盘预算 | 删可选消融/任务，不删基线和证据 |
| 公开仓库泄露内部信息 | 附件包含内部运行环境 | 公共 artifact 脱敏检查 | 内部材料不上传，公开摘要替代 |

M1 的“至少两个任务重复完成”是运行资格判据，不是要求总成功率达到某个漂亮数字；如仅一个任务可靠，提交范围缩减审核，而不是偷偷替换三个任务。

## 7. 授权与审核关口

初始放行 M0–M1（含总计最多 24 次开发 episode 预算；正式校准/测试未授权）。CPU 级 schema 和 mock 单元测试可并行，不冒充 runtime 验证。

- R1：M0–M1 证据审核，放行 M2–M3 开发/校准或提出修复。
- R2：shadow、标签、Gate 和 protocol lock 审核，放行 M4 正式测试。
- R3：完整实验与分析审核，放行最终交付或要求纠错。

审核不要求每个小函数都等待 GPT；只有关口、超预算和科学协议变更需要显式放行。无后台自动审核承诺。

## 9. 资源和总运行预算

先单模型 server、单主环境、单 shadow 顺序运行；shadow 不再加载第二份 GR00T。优先使用已有授权 GPU，不在公开文档存具体主机和账户。

起始预算：开发 <=24；校准 3任务×5初始化×3条件=45 baseline，可选相应45 governed；正式 3任务×10初始化×3条件×2系统=180 runs。合计约249–294 episode runs。规模须在 R2 前按真实成本、事件数和可用初始化确认。

三个条件复用同一初始化时，正式实验是90个配对场景，但仅30个初始化 cluster，不能当作90个独立初态。

## 11. 完成定义与允许结论

项目完成意味着建立了“治理问题→要求→实现→可核验证据→局限”的链条，不要求预设正效果。零违规且零任务完成不是可用系统的证明；自然事件不足与受控故障有效必须分开说。

在相同随机流、相同执行轨迹、仅允许拒绝终止的条件下，G 的成功集合应是 B0 成功集合的子集；不能把本设计包装成任务修复算法。若观察到成功率提升，首先审查推理随机性、终止规则、配对与副作用。
